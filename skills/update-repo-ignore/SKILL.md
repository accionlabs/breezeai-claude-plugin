# Update `.repoignore` files

Scans repos for files and folders that add noise to a semantic code graph — auto-generated code, build tooling config, CI/CD pipelines, static assets, documentation, test infrastructure — and writes accurate `.repoignore` patterns for each.

## What belongs in `.repoignore`

Exclude anything that is **not hand-authored business logic**. Use this as a checklist — not all categories will apply to every repo.

### Auto-generated code

| Trigger | Patterns |
|---|---|
| EF Core (C#) | `**/Migrations/**/*.Designer.cs`, `**/*ModelSnapshot.cs` |
| ORM codegen (any) | `*.generated.ts`, `*.generated.cs`, `**/*_gen.go`, `**/*_pb.py`, `**/*_pb2.py` |
| Protobuf / gRPC | `**/*.pb.go`, `**/*.pb.cc`, `**/*.pb.h`, `*_grpc.pb.*` |
| GraphQL codegen | `**/generatedModels/`, `**/__generated__/`, `**/generated/` (codegen output), `schema.json`, `**/*.gql` (downloaded schema dumps) |
| OpenAPI / Swagger | `**/generated-client/`, `**/openapi-generated/` |
| i18n extraction | `**/*.xlf`, `**/*.xmb`, `**/*.po`, `**/*.pot` |
| Rails schema | `db/schema.rb`, `db/structure.sql` |
| Any file with `// <auto-generated />`, `// Code generated`, `# This file was automatically generated`, or `@generated` header |

### Build artifacts & caches

| Stack | Patterns |
|---|---|
| JavaScript / Node | `**/dist/`, `**/build/`, `**/.next/`, `**/.nuxt/`, `**/.svelte-kit/`, `**/.remix/`, `**/.expo/` |
| TypeScript / Angular / NX | `**/.nx/`, `**/.angular/`, `**/coverage/` |
| Java / Kotlin / Gradle | `**/build/`, `**/.gradle/`, `**/*.class`, `**/*.jar` (generated) |
| Maven | `**/target/` |
| .NET | `**/bin/`, `**/obj/` |
| Python | `**/__pycache__/`, `**/*.pyc`, `**/*.pyo`, `**/.pytest_cache/`, `**/*.egg-info/` |
| Rust | `**/target/` |
| Go | (binaries are typically gitignored already) |
| Ruby | `**/coverage/`, `**/.bundle/` |
| Elixir | `**/_build/`, `**/deps/` |
| Swift / iOS | `**/*.xcworkspace/xcuserdata/`, `**/DerivedData/` |
| CocoaPods | `**/Pods/` |
| General | `**/coverage/`, `**/.cache/`, `**/.turbo/` |

### Dependencies

| Stack | Patterns |
|---|---|
| JavaScript | `**/node_modules/` |
| Python | `**/venv/`, `**/.venv/`, `**/site-packages/` |
| PHP | `**/vendor/` |
| Ruby | `**/vendor/bundle/` |
| .NET | (restored to `obj/` — already covered above) |

`package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `Gemfile.lock`, `Pipfile.lock`, `poetry.lock`, `Cargo.lock`, `go.sum`, `composer.lock`

### CI/CD pipelines

`azure-pipelines.yml`, `azure-pipelines/`, `.github/workflows/`, `.gitlab-ci.yml`, `.circleci/`, `Jenkinsfile`, `bitbucket-pipelines.yml`, `.travis.yml`, `cloudbuild.yaml`

### Code quality / static analysis

`sonar-project.properties`, `.sonarlint/`, `.sonarcloud.properties`, `.codeclimate.yml`, `.deepsource.toml`

### Editor / IDE config

`.vscode/`, `.cursor/`, `.idea/`, `.eclipse/`, `.claude/`, `.editorconfig`, `*.iml`, `*.iws`, `*.ipr`

### Git hooks

`.husky/`, `.lefthook.yml`, `.pre-commit-config.yaml`

### Linting / formatting config

`.eslintrc*`, `eslint.config.*`, `.prettierrc*`, `.stylelintrc*`, `.rubocop.yml`, `.flake8`, `pyproject.toml` (if only linting config), `.golangci.yml`, `checkstyle*.xml`, `phpcs.xml`

### Build / framework / test config (no logic)

`tsconfig*.json`, `angular.json`, `nx.json`, `project.json`, `jest.config.*`, `vitest.config.*`, `webpack.config.*`, `vite.config.*`, `rollup.config.*`, `esbuild.config.*`, `ng-package.json`, `nest-cli.json`, `babel.config.*`, `karma.conf.*`, `pytest.ini`, `setup.cfg`, `build.gradle`, `pom.xml` (Maven config), `*.csproj` (project config only — no logic), `*.sln`, `*.sln.DotSettings`, `nuget.config`, `Makefile` (if only build targets), `CMakeLists.txt`

### Docker / infrastructure / deployment

`Dockerfile`, `Dockerfile.*`, `.dockerignore`, `docker-compose*.yml`, `*.tf` (Terraform), `*.tfstate`, `*.tfvars`, `.terraform/`, `helm/`, `k8s/`, `kubernetes/`, `charts/`, deployment shell scripts

### Static assets (binary / media)

`**/*.woff`, `**/*.woff2`, `**/*.ttf`, `**/*.eot`, `**/*.otf`, `**/*.png`, `**/*.jpg`, `**/*.jpeg`, `**/*.gif`, `**/*.webp`, `**/*.bmp`, `**/*.ico`, `**/*.svg` (under `assets/` dirs), `**/*.mp4`, `**/*.mov`, `**/*.webm`, `**/*.pdf` (binary assets), `**/*.zip`, `**/*.tar.gz`

### Documentation

`docs/`, `**/*.md`, `**/*.rst`, `**/*.adoc`, `CHANGELOG*`, `LICENSE`, `AGENTS.md`, `CLAUDE.md`

### Test infrastructure (not business logic)

`**/e2e/`, `**/cypress/`, `**/__mocks__/`, `**/fixtures/` (test data), `**/test-helpers/`, `jest-mocks/`, `spec/support/` (Ruby), `tests/fixtures/`, `**/testdata/` (Go), C# test projects (`*.Tests/`, `*.IntegrationTests/`, `*.UnitTests/`)

### API client / HTTP workspaces

`postman/`, `.yaak/`, `.insomnia/`, `.httpyac/`

### Environment / secrets

`.env`, `.env.*`, `*.env`, `secrets.*`

### Misc tooling

`GitVersion.yml`, `dependabot.yml`, `.github/dependabot.yml`, scratchpad files (`*.txt` ad-hoc queries), `scripts/` (one-off dev utility scripts — judge case by case)

---

**Do NOT exclude:**
- Hand-authored source code in any language
- Manifest / project descriptor files consumed at runtime (`package.json`, `Cargo.toml`, `pyproject.toml` with real config, `go.mod`)
- Application config files consumed at runtime (`appsettings.json`, `config.yml`, `settings.py`, etc.)
- Hand-authored DB migration files containing Up/Down logic — but DO exclude their auto-generated snapshot twins
- Hand-authored `Makefile` targets that encode real build knowledge (judge by content)

## Procedure

### 1. Identify repos to scan

Ask the user which repo(s) to scan if not already clear. For a monorepo, list the sub-repos and confirm scope, or scan all if instructed.

### 2. Detect the stack

Before scanning, do a quick top-level directory listing of each repo to identify the language and framework. This tells you which categories from the checklist above are relevant and what additional patterns to look for.

### 3. Launch one Explore agent per repo (in parallel)

For each repo, launch an `Explore` agent (use `run_in_background: true` when scanning multiple):

> Scan `<repo-root>` thoroughly for files and folders that contain no hand-authored business logic — auto-generated files, build tooling config, CI/CD pipelines, static assets, documentation, test infrastructure, lock files, editor configs, etc.
>
> For each item found: give the exact relative path from the repo root and a one-line reason why it's noise.
>
> Check for (adapt to the stack you find): `.husky/`, `.github/`, `.vscode/`, `.cursor/`, `.idea/`, `.claude/`, `docs/`, CI pipeline files, `sonar-project.properties`, `.sonarlint/`, `Dockerfile`, `docker-compose*.yml`, `postman/`, `.yaak/`, build config files (`tsconfig*.json`, `jest.config.*`, `webpack.config.*`, `vite.config.*`, `babel.config.*`, `pytest.ini`, `build.gradle`, `pom.xml`), `project.json`, `ng-package.json`, `**/*.md`, `**/*.xlf`, binary assets (`**/*.woff`, `**/*.woff2`, `**/*.png`, `**/*.jpg`, `**/*.webp`, `**/*.svg` under assets dirs, `**/*.ico`, `**/*.mp4`), schema dumps (`schema.json`, `*.gql`), lock files, `__pycache__/`, `*.pyc`, `venv/`, `.gradle/`, `target/`, `Pods/`, `.terraform/`, `.env.*`, test project folders, coverage outputs, scratchpad files, and any files with auto-generated headers (`// <auto-generated />`, `// Code generated`, `@generated`, `# This file was automatically generated`).
>
> Report everything — list exact paths, not just patterns.

### 4. Synthesise findings into `.repoignore` patterns

For each repo, read the current `.repoignore` (if it exists), then write an updated version with clean sections:

```
# <Category label>
<pattern>
<pattern>
```

Rules for patterns:
- Use `**/foo/**` for folders that may appear at any depth
- Use `foo/**` for folders that only appear at the repo root
- Use `**/*.ext` for file-type exclusions that apply everywhere
- Use specific paths when a broader glob would accidentally exclude real code
- Group related patterns under a comment heading
- Only add patterns for things that actually exist — keep it specific, not aspirational

### 5. Write the file

Write `.repoignore` at the repo root. If it already exists, read it first, preserve correct existing patterns, and add new ones. Don't remove patterns without confirming they're wrong.

### 6. Verify

After writing, briefly confirm:
- The `.repoignore` covers the major noise sources found
- No hand-authored source files are accidentally excluded
- The patterns are valid glob syntax
